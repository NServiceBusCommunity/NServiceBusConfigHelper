# Adding features to an NServiceBus endpoint

Generated by the [NServiceBus wizard](https://nservicebuscommunity.github.io/NServiceBusConfigHelper/add?step=output&transport=AzureServiceBus&persistence=CosmosDb&features=Sagas,Outbox,FluentValidation). The files next to this guide are changes to merge into an existing endpoint, not a solution. Adding: Sagas, Outbox, FluentValidation.

Package versions: the newest stable releases as of 2026-10-01; nuget.org was not checked when this was generated.

## Steps

1. Merge the `PackageVersion` items from `Directory.Packages.props.fragment.xml` into `Directory.Packages.props`. Without central package management, put each version on the matching `PackageReference` in the next step instead.
2. Merge the `PackageReference` items from `Endpoint.csproj.fragment.xml` into the endpoint's project file.
3. Merge `Program.fragment.cs` into the code that configures the endpoint. It is grouped by where each statement goes, and refers to the endpoint's own `builder`, `endpointConfiguration` and `transport` variables.
4. Copy `Sagas/OrderSaga.cs`, `Sagas/OrderSagaData.cs`, `Sagas/CancellationWindowElapsed.cs`, `Validation/PlaceOrderValidator.cs` into the endpoint project, and change the namespace `SampleEndpoint` to the project's own.
5. Those files refer to sample messages and a sample handler, which are in `Samples/`. Point the copied code at the endpoint's own messages instead, or copy the samples too.
6. Build and run the endpoint.

## What each feature adds

### Sagas

A long-running process with its own state: a sample saga that is started by an event and completes on a timeout. [Documentation](https://docs.particular.net/nservicebus/sagas/).

Files: `Sagas/OrderSaga.cs`, `Sagas/OrderSagaData.cs`, `Sagas/CancellationWindowElapsed.cs`.

 * A saga's state is stored by the persistence. Messages for one saga instance are handled one at a time: a concurrent update fails and is retried.
 * A timeout is a message sent to the saga itself with a delay, so it survives a restart.

### Outbox

Stores a handler's outgoing messages with its data in one transaction, so a redelivered message is neither processed nor sent twice. [Documentation](https://docs.particular.net/nservicebus/outbox/).

```cs
// The outbox takes over from the transport's transaction, which then only covers the receive.
transport.TransportTransactionMode = TransportTransactionMode.ReceiveOnly;
endpointConfiguration.EnableOutbox();
```

 * With the outbox on, the transport has to receive in `ReceiveOnly` mode, which `Program.cs` sets on the transport: consistency between the data and the outgoing messages comes from the outbox record, not from a transaction spanning the queue and the database.

### FluentValidation

Validates messages with FluentValidation as they are received and sent: a sample validator for the sample command. An NServiceBus Community extension. [Documentation](https://github.com/NServiceBusCommunity/NServiceBus.Community.Validation#nservicebusfluentvalidation).

```cs
builder.Services.AddValidatorsFromAssemblyContaining<PlaceOrderValidator>();

endpointConfiguration.UseFluentValidation();
```

Files: `Validation/PlaceOrderValidator.cs`.

 * A message that fails validation on the way in is not retried: it goes straight to the error queue. One that fails on the way out throws where it is sent. Pass `incoming: false` or `outgoing: false` to `UseFluentValidation` to check one direction only.

## Worth knowing

 * **Outbox, Azure Cosmos DB**: With Cosmos DB the outbox record gets a partition key made from the endpoint name and the message id unless one is mapped. A handler that also writes its own documents needs them in the same partition to commit with the outbox record: map the key with `persistence.TransactionInformation()`; see [transactions](https://docs.particular.net/persistence/cosmosdb/transactions).
 * **FluentValidation**: FluentValidation is an NServiceBus Community extension: MIT licensed, and developers who use it are expected to [become patrons](https://github.com/NServiceBusCommunity/Home#community-backed).

==== Sagas/OrderSaga.cs

using SampleEndpoint.Messages;

namespace SampleEndpoint;

/// <summary>
/// Starts when an order is placed, then waits for the cancellation window to pass. There is one
/// instance per order, found by <see cref="OrderSagaData.OrderId"/>.
/// </summary>
public class OrderSaga(ILogger<OrderSaga> logger) :
    Saga<OrderSagaData>,
    IAmStartedByMessages<OrderPlaced>,
    IHandleTimeouts<CancellationWindowElapsed>
{
    protected override void ConfigureHowToFindSaga(SagaPropertyMapper<OrderSagaData> mapper) =>
        mapper.MapSaga(saga => saga.OrderId)
            .ToMessage<OrderPlaced>(message => message.OrderId);

    public async Task Handle(OrderPlaced message, IMessageHandlerContext context)
    {
        logger.LogInformation("Order {OrderId}: waiting for the cancellation window", message.OrderId);
        await RequestTimeout<CancellationWindowElapsed>(context, TimeSpan.FromSeconds(10));
    }

    public Task Timeout(CancellationWindowElapsed state, IMessageHandlerContext context)
    {
        logger.LogInformation("Order {OrderId}: cancellation window elapsed, order confirmed", Data.OrderId);
        MarkAsComplete();
        return Task.CompletedTask;
    }
}

==== Samples/Handlers/PlaceOrderHandler.cs

using SampleEndpoint.Messages;

namespace SampleEndpoint;

public class PlaceOrderHandler(ILogger<PlaceOrderHandler> logger) :
    IHandleMessages<PlaceOrder>
{
    public async Task Handle(PlaceOrder message, IMessageHandlerContext context)
    {
        logger.LogInformation("Order {OrderId}: placed for {Product}", message.OrderId, message.Product);

        // Publishing through the handler's context makes the event part of handling this message:
        // it is only sent once the handler has succeeded.
        await context.Publish(
            new OrderPlaced
            {
                OrderId = message.OrderId
            });
    }
}
