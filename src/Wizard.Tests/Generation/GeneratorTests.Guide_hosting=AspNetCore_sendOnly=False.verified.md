# SampleEndpoint

An NServiceBus endpoint generated by the [NServiceBus wizard](https://nservicebuscommunity.github.io/NServiceBusConfigHelper/new?step=output&host=AspNetCore&transport=Learning&persistence=Learning&serializer=SystemJson&tests=XunitV3). That link reopens the wizard with the same answers.

## What is in the solution

 * `src/SampleEndpoint`: the endpoint `SampleEndpoint`, hosted as an ASP.NET Core application.
 * `src/SampleEndpoint.Tests`: xUnit v3 tests.
 * `CLAUDE.md` and `.github/copilot-instructions.md`: the same facts as this guide, written for an AI coding assistant.
 * Transport: [Learning](https://docs.particular.net/transports/learning/).
 * Persistence: [Learning](https://docs.particular.net/persistence/learning/).
 * Serializer: [System.Text.Json](https://docs.particular.net/nservicebus/serialization/system-json).

Package versions: the newest stable releases as of 2026-10-01; nuget.org was not checked when this was generated.

## Before the first run

1. Install the .NET SDK 10.0.403 or a later feature band; `global.json` pins it.
2. NServiceBus is licensed by Particular Software. See [licensing](https://docs.particular.net/nservicebus/licensing/) for the options and for where the licence file goes.

## Run it

```sh
dotnet run --project src/SampleEndpoint
```

Then place an order, for example with `curl -X POST "http://localhost:5000/orders?product=Widget"`. The log shows `PlaceOrder` being handled, and the `OrderPlaced` event it publishes being handled in turn.

## How the endpoint is configured

All of it is in `src/SampleEndpoint/Program.cs`, in the order below.

### Transport: Learning

Messages are files in a .learningtransport folder. Nothing to install; for development only. [Documentation](https://docs.particular.net/transports/learning/).

```cs
var transport = new LearningTransport();
```

 * The learning transport writes each message as a file under `.learningtransport` at the solution root, which makes them easy to inspect. It is not for production: choose a real transport before deploying.

### Persistence: Learning

Sagas are json files in a .sagas folder under the build output. Nothing to install; for development only. [Documentation](https://docs.particular.net/persistence/learning/).

```cs
endpointConfiguration.UsePersistence<LearningPersistence>();
```

 * The learning persistence keeps each saga as a json file under `.sagas` in the build output folder. It has no outbox, and is not for production.

### Serializer: System.Text.Json

Json with the serializer built into .NET. No extra package; the usual choice. [Documentation](https://docs.particular.net/nservicebus/serialization/system-json).

```cs
endpointConfiguration.UseSerialization<SystemJsonSerializer>();
```

### Error queue

A message that still fails after its retries is moved to the `error` queue, with the exception in its headers, so the endpoint can carry on with the next one.

```cs
// Where a message goes once every retry has failed. ServiceControl reads this queue.
endpointConfiguration.SendFailedMessagesTo("error");
```

### Installers

The endpoint creates its queues, topics and tables when it starts. That is convenient in development. In production, run [installers](https://docs.particular.net/nservicebus/operations/installers) as a deployment step instead, with rights the running endpoint does not need.

```cs
// Creates the queues, topics and tables the endpoint needs when it starts. Convenient in development.
// In production, run installers as a deployment step, with rights the running endpoint does not need.
endpointConfiguration.EnableInstallers();
```

## The sample messages

 * `Messages/PlaceOrder.cs` is a command: a request for one endpoint to do something.
 * `Messages/OrderPlaced.cs` is an event: something that has happened, which any number of endpoints can subscribe to.
 * `Handlers/PlaceOrderHandler.cs` handles the command and publishes the event. `Handlers/OrderPlacedHandler.cs` handles the event, which is also what subscribes the endpoint to it.
 * `OrderSubmitter.cs` sends the command from outside a handler, through `IMessageSession`. Inside a handler, always send and publish through the context the handler is given, so the outgoing messages belong to the message being handled.
 * `POST /orders` in `Program.cs` submits an order.

## Tests

`src/SampleEndpoint.Tests` uses xUnit v3 and [NServiceBus.Testing](https://docs.particular.net/nservicebus/testing/), whose fakes record what a handler sends and publishes, so nothing needs a transport.

```sh
dotnet test
```

## Worth knowing

 * **Learning transport, Learning persistence**: The Learning transport and Learning persistence are for development. Choose a production one before deploying.
